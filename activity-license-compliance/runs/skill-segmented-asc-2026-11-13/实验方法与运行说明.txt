新数据集许可证 ASC 分段提取实验

输入
paper/evaluation/skill-supply-chain-2026-11-13/filtered-no-unlicense/retained_relationships.csv
6,113 条关系。以 normalized_downstream_license / normalized_upstream_license 为标签，
自定义许可按仓库精确映射，专有平台许可按资产 URL 优先匹配。
本实验只提取许可证条款，不执行供应链冲突检测，也不产生新的违规数量。

原文与映射
68 个原文文件、67 个不同 SHA-256 文本。相同文本只抽取一次，并保留文件别名。
21 份不同文本来自自定义原文目录。旧 ASC 与旧冲突判定均不作为提取输入。
依照本次“所有涉及到的许可证”要求，纳入新输入中的 GPL-2.0 / LGPL。
LGPL-2.1 原文补自 https://www.gnu.org/licenses/old-licenses/lgpl-2.1.txt。
LGPL-3.0 对 GPL-3.0 的引用关系保存在 inventory.json.dependencies；后续解释须组合使用。
GPL-2.0 原文文件名包含 or-later，但不因此把输入标签强制升级为 or-later 授权。
MIT OR Apache-2.0 保留 OR 表达式，分别抽取原文；后续不得把两者义务无条件合并成 AND。

沿用的用户指定映射应与法律事实区分：
1. gemma 标签的主许可映射到 Apache-2.0。
2. Llama 未指明版本时使用 Llama 4。
其中 llama.cpp / LlamaIndex / LlamaParse 等资产名称并不能证明使用 Meta 模型许可证。
相关关系在 inventory.json.mappings.notes 中标记。无缺失原文映射不等于映射全部经专家确认。
商业平台名称下也可能混有本地模型/SDK；本轮遵循输入标签和资产 URL，不重新推断资产类型。

分段方法
1. 按空行划分自然段；过长段落沿现有行边界细分，保留原文件行号。
2. 以约 8,500 字符目标合并完整段落，总计 148 个目标段。
3. 每个原文非空行恰好属于一个目标段；程序已检查无漏行和重复分配。
4. 附带邻近上下文、章节索引和原文中的定义段，均与可引用目标正文区分。
5. 对较长定义上下文，按目标段术语相关性选取，预算 14,000 字符；省略范围明确列出。
   定义段本身仍会作为目标正文接受提取，不会因上下文裁剪而从实验消失。
6. 不向每次调用重复发送整个许可证，不复用旧实验稀疏规则。

提取与审查
使用现有配置中的 gpt-6-luna Responses API，中转站端点和密钥来源保持现有配置。
每个条目保存 A/S/C、条款名称、精确原文行号及引文、主体、对象范围、条件解释。
同一条目只使用一个活动和一个对象，不机械展开活动×对象笛卡尔积。
条目附 obligation_items：具体义务内容、承担者、对象、触发条件，以及履行或不实施类型。
这些是许可证级义务候选，尚不是展开到 6,113 条供应链关系的义务集合。
服务/输入/输出可以用 OriginalArtifact 这一结构类别表示，实际对象在 scope_note 中明确。
具体条件使用布尔表达式保留 AND/OR、例外、数值门槛、期限和单独授权。
不将保留声明写成“必须分发”，不将支付供应商费用写成“必须向第三方收费”。
AGPL、MIT、Apache、非商业许可与 Gemini 输出权利的常见误判边界直接写入提示词。

每个目标自然段必须对应 paragraph_audit 中的一条记录：
MODELED：模型自评已建模，且必须引用与该段相交的条目。
CONTEXT：定义、标题或解释上下文，不是独立授权。
NONOPERATIVE：不属于活动约束范围的材料，并说明原因。
UNRESOLVED：存在未覆盖或无法可靠表达的实质内容，保留原因。
即使引用了整段，也不能仅凭引用长度认定覆盖全部语义。
纯担保/责任免责、管辖和许可证应用示例不会被伪造成 Use/UNSPECIFIED 规则。

自动校验与修复
检查 JSON、ASC 枚举/布尔表达式、引用行号、每段审查记录、条目引用、义务必要字段。
首次有效结果如仍标记 UNRESOLVED，可追加一轮针对性复查；不编造外部文件内容。
输出错误或网络失败最多三次尝试；失败记录后继续其他任务。
最终修复阶段对反复失败且包含多个自然段的目标段，最多再做两级二分，
子段分别校验通过后才合并，不通过复制旧条目或手工编造条目来补齐。
网络超时已从初始 150 秒调整为 300 秒，避免较长生成反复被中断。
所有请求和原始响应保留；再次运行按完整请求哈希复用已验证结果。
API key 只从现有配置读取，不写入请求、响应或报告文件。
初始两个试运行用于改进提示词，其原始响应仍保留，但不能混入最终版本的完成率。

指标解释
“148 段都处理完成”是输入处理完整性；“MODELED”是模型自评。
二者都不等于专家确认的语义覆盖率、准确率或召回率。
不能通过增加重复 ASC 条目人为提高覆盖率。
真实覆盖率需要原文优先建立的专家参考集合，按义务内容、对象、主体和条件逐项匹配。
摘要中的 token 数累计所有落盘响应，包括试运行和修复尝试。
中转站计价未核验，因此不据此捏造人民币/美元费用。

文件用途
inventory.json：输入哈希、原文清单、逐关系映射、假设与依赖。
plan.json：每段原文范围、自然段清单、输入字符数。
extraction_prompt.txt：本次完整提示词。
requests/、responses/：原始模型请求、响应；响应含服务端返回的用量。
validated/：通过结构与证据位置校验的分段结果。
partial/：复查前的中间结果。
errors/：各次错误，保留原始失败轨迹。
progress/：每段最近的执行状态。
licenses/：按原文内容哈希命名的逐许可证 ASC 文件，内含原文文件名和别名。
structured_asc.json：本实验独立 ASC 汇总；不覆盖历史 data/structured_asc_v1.json。
summary.json：已完成段数、待处理段、条目数、段落审查计数和 token 用量。
execution_state.json：监督程序状态；两批任务结束后自动做最终修复、核验及报告。
逐许可证提取统计.txt、提取结果报告.txt：可读统计；运行中为阶段结果，完成后自动更新。

代码
scripts/extract_segmented_asc.py：输入映射、自然段切分、上下文选择、API 调度、校验、汇总。
tests/test_segmented_asc.py：漏段、错误活动义务、缺失义务条件等回归检查。
scripts/audit_segmented_asc.py：核对输入/原文不变、非空行覆盖、引文、规则编号并生成报告。
复用既有 Responses 客户端和配置模块；不改动历史冲突检测程序。

运行（工具目录下）
python3 scripts/extract_segmented_asc.py --execute --workers 4
仅重建清单及汇总，不调用 API：
python3 scripts/extract_segmented_asc.py
单份原文调试：
python3 scripts/extract_segmented_asc.py --execute --source LICENSE-MIT.txt --workers 1
